# K 线量化回测模块需求说明

> 文档状态：v1.1 首期交付完成（阶段 8 的 19 条验收标准于 2026-07-11 全部通过）
> 首期交付实现提交：`5c89169`；盈亏比功能补全提交：`892cdd6`
> 版本：v1.1
> 日期：2026-07-10
> 适用项目：TradingAgents-AShare
> 基础版本：v1.0（提交 `573c827`）

## 1. 背景与目标

在当前股票分析页面增加一个独立的 K 线量化回测模块。模块使用 AkShare 历史日 K 数据，以均线、斐波那契回撤和趋势线构造确定性交易策略，在历史市场中模拟买卖，并在完整扣除佣金、税费、过户费和滑点后评价策略表现。

默认回测区间按 `Asia/Shanghai` 时区动态计算为“上一完整自然年”。例如当前日期处于 2026 年时，默认区间为 2025-01-01 至 2025-12-31；用户可以修改证券、日期、指标和交易成本参数。

核心目标：

- 在当前分析页直接回测当前证券。
- 只使用回测时点已经出现且已经确认的数据，杜绝未来数据泄漏。
- 支持 A 股普通股票与场内基金，并按品种应用不同费率。
- 使用净收益而非毛收益评价短线策略。
- 在同一份数据和费率口径下比较多个独立策略账户与买入持有基准。
- 回测可复现、结果可保存、参数和信号可审计。
- 不调用大模型，不影响现有多智能体分析流程。

## 2. 范围

### 2.1 首期包含

- 单只证券、日线级别回测。
- A 股普通股票和场内基金（优先支持 ETF）。
- 每个被选策略使用独立虚拟资金账户。
- 仅做多，不允许卖空、融资或融券。
- AkShare 日 K 数据。
- 均线、斐波那契回撤、趋势线。
- 固定止损、固定止盈。
- 次交易日开盘执行。
- 100 股/份整数交易单位。
- 佣金、印花税、过户费、滑点。
- 停牌、涨跌停、T+1 和资金不足约束。
- 策略收益与买入持有基准比较。
- 回测结果持久化和历史结果查看。

### 2.2 首期不包含

- 指数回测。指数没有与普通证券完全等价的真实交易成本结构；页面选择指数时应明确提示“首期暂不支持指数回测”。
- 多证券组合、行业轮动和跨品种调仓。
- 分钟级、逐笔或盘口级回测。
- 融资融券、卖空、期权和期货。
- 大模型逐日生成买卖信号。
- 自动参数寻优、机器学习训练。
- 实盘自动下单。
- 周线回测。指标接口需保持 bar 粒度无关，为二期周线重采样预留。
- 对分红税、申购赎回费等非二级市场普通买卖费用进行复杂建模。

## 3. 与现有回测服务的关系

仓库现有 `api/services/backtest_service.py` 属于“多智能体逐日分析并验证后续涨跌”的实验型服务：它会反复调用大模型、按采样日分析，并以固定持有天数评价信号。

新模块与其目标和计算方法不同：

| 项目 | 现有实验型回测 | 新 K 线量化回测 |
|---|---|---|
| 信号来源 | 多智能体/大模型 | 确定性技术指标 |
| 数据粒度 | 采样日期 | 每个交易日 |
| 交易账户 | 无完整资金账户 | 每策略独立的完整现金和持仓账户 |
| 成本 | 未完整计入 | 逐笔计入全部成本 |
| 执行规则 | 当日参考价加固定持有期 | 当日收盘出信号，次日开盘执行 |
| 结果 | 信号正确率 | 净值、回撤、逐笔交易、信号审计和成本归因 |

实现时不得直接扩写或修改现有回测算法。新模块使用独立服务、数据模型和 API；现有 `/v1/backtest` 接口及 `api/services/backtest_service.py` 的行为保持不变。

## 4. 数据需求

### 4.1 独立 AkShare 数据入口

新回测模块建立独立、可审计的 AkShare 标准化入口，不直接复用当前 `/v1/market/kline` 返回值，也不使用会静默回退到其他供应商的通用数据路由。用户可在创建 run 前显式选择供应商；一个 run 从开始到结束只允许调用所选供应商，失败后如需换源必须创建新的 run。

原因：现有行情标准化主要面向图表和智能分析，复权方式固定，不能可靠保留全部回测字段；部分来源的 `amount/Amount` 会进入 Volume 映射，无法满足成交额、缓存版本和数据哈希要求。

独立入口要求：

- 接口库严格限定为 AkShare；股票支持显式选择东方财富、新浪或腾讯，场内基金支持东方财富，新浪仅在不复权口径下开放，暂不支持腾讯。
- 2026-07-11 起，因东方财富历史接口持续断连，默认源临时按品种调整为：普通股票使用腾讯前复权、场内基金使用新浪原始数据、北交所股票使用新浪前复权。东方财富仍保留为可手动选择的数据源；每个 run 继续锁定唯一供应商，连接失败时不得静默回退，界面应提供“使用其他供应商重新运行”的明确操作。
- 记录实际调用的 AkShare 接口名称和 AkShare 版本。
- 复用项目现有 AkShare 并发锁，避免与智能分析同时抓取时冲突。
- 允许选择前复权、不复权等支持的复权方式；默认前复权。
- 标准化和校验所有字段，不生成伪造值。
- 当前交易日尚未收盘时，排除未完成的当日 K 线；交易日和收盘状态按 `Asia/Shanghai` 判断。
- 回测不支持指数；数据入口发现指数代码时返回明确的“不支持”错误。

标准字段：

- 交易日期
- 开盘价
- 最高价
- 最低价
- 收盘价
- 成交量
- 成交额（源数据可用时）
- 涨跌幅（源数据可用时）
- 换手率（源数据可用时）

OHLCV 是运行回测的最低必要字段。扩展字段不可用时必须标注缺失，不得将其他字段错误映射后冒充。

默认采用前复权口径，并在结果中记录数据源、接口、版本、复权方式、获取时间和实际数据区间。策略和买入持有基准必须使用相同价格口径。

前复权价格具有时变性：未来除权除息可能导致历史前复权价格整体重算。系统按复权后价格计算成交额与费用，与真实历史成交额可能存在轻微偏差；首期接受此近似，并通过数据版本和哈希保证同一 run 的结果可追溯。

### 4.2 预热数据

系统必须额外获取统计开始日期之前至少 120 个交易日的数据，用于计算 MA20、60 日波段和趋势线。

预热期仅用于指标计算：

- 不允许在开始日期前成交。
- 不计入回测收益和统计区间。
- 预热数据不足时必须提示，不得静默用短窗口代替。

### 4.3 缓存、版本与数据哈希

- 按证券、供应商接口、复权方式、日期范围和数据版本缓存标准化 K 线，不同供应商缓存不得混用或拼接。
- 缓存默认 TTL 为 7 个自然日，可配置。
- 缓存记录获取时间、AkShare 版本、实际接口、实际数据区间和数据哈希。
- 用户可以选择使用有效缓存或强制刷新。
- AkShare 暂时不可用时，可以使用覆盖完整区间且未过期的有效缓存；否则返回明确错误。
- 无有效缓存且 AkShare 发生连接类错误时，同一接口默认重试 3 次，按 1 秒、2 秒指数退避；每次尝试、等待时间、异常类型和最终耗尽均写入日志。重试次数与基础退避时间允许通过环境变量调整。
- 重试耗尽后 run 必须终止为 `failed`，错误码为 `data_source_connection_failed`，不得继续计算或生成伪结果。
- 腾讯 `stock_zh_a_hist_tx` 返回的 `amount` 表示成交手数而非成交额；进入标准化模型前必须转换为 `volume = amount × 100`（股），标准成交额保持缺失，禁止复用该列污染成交额。
- 结果页应区分“加载范围（含预热 K 线）”与“统计区间”；若全部买单因 `insufficient_cash` 取消，应明确提示初始资金不足以购买一手。
- 用户明确选择其他供应商后创建的是独立新 run，新 run 的参数快照、实际接口和数据哈希必须完整记录。
- 每次 run 必须保存实际使用的数据哈希、缓存版本和实际数据区间。

数据哈希使用标准化、按交易日期升序排列的 K 线序列计算 SHA-256。哈希输入字段及序列化规则必须固定，至少包含日期、OHLCV、复权方式；字段顺序、空值表示和数值精度必须确定，不能依赖 DataFrame 或字典的偶然输出格式。

## 5. 品种识别与费率

### 5.1 品种识别

系统根据证券代码和 AkShare 基础信息识别 A 股普通股票或场内基金，并允许用户手动覆盖。费率按配置档案管理，API 和数据结构应允许以后增加其他品种。

识别要求：

- 支持 `.SH`、`.SZ` 和 `.BJ` 的规范代码。
- 北交所代码、板块和涨跌停阈值由新模块独立标准化，不完全依赖现有通用 `_normalize_symbol()`。
- 指数必须识别并拒绝，不能误判为股票。
- 自动识别结果和手动覆盖结果都写入参数快照。

### 5.2 默认费率

| 项目 | A 股股票 | 场内基金 |
|---|---:|---:|
| 买卖佣金 | 成交额 × 0.000115（万 1.15） | 成交额 × 0.0001（万 1） |
| 最低佣金 | 0 元（免 5） | 0 元（免 5） |
| 印花税 | 卖出成交额 × 0.0005（万 5） | 0 |
| 过户费 | 成交额 × 0.00001（万 0.1），双向 | 0 |
| 买入滑点 | 0.1%，可调 | 0.1%，可调 |
| 卖出滑点 | 0.1%，可调 | 0.1%，可调 |

费率均为默认值，不得硬编码进策略。前端可调，后端将实际费率完整保存到每次回测快照中。

### 5.3 费用公式

```text
买入成交价 = 次日开盘价 × (1 + 买入滑点率)
卖出成交价 = 次日开盘价 × (1 - 卖出滑点率)

佣金 = max(成交额 × 佣金率, 最低佣金)
印花税 = 卖出成交额 × 对应品种印花税率
过户费 = 成交额 × 对应品种过户费率

买入现金减少 = 买入成交额 + 买入佣金 + 买入过户费
卖出现金增加 = 卖出成交额 - 卖出佣金 - 印花税 - 卖出过户费
滑点成本 = |实际成交价 - 参考开盘价| × 成交数量
```

成交价已经包含滑点，滑点成本只用于归因展示，不得再次从现金扣除。

资金账户、成交价格和费用使用 `Decimal` 十进制定点计算，按明确的舍入规则保留到分；技术指标允许使用浮点数。佣金中已包含的规费不得再次扣除。

## 6. 账户、信号与成交模型

### 6.1 多策略独立账户

一次回测 run 在同一份 K 线数据、同一账户参数和同一费率快照下，对用户勾选的策略集合分别独立模拟。每个策略拥有独立现金、持仓、订单、交易和净值，策略之间不得共享或影响资金。

默认账户参数：

- 初始资金：100,000 元，可调。
- 最大仓位：100%，可调。
- 每次买入最大可用金额 = 当前可用现金 × 最大仓位比例。
- 同一策略同一时刻最多持有一个该证券仓位。
- 买入数量为 100 股/份的整数倍。
- 使用扣除预计费用后能够买入的最大整数手数量。
- 不允许现金为负。
- 不允许加杠杆。
- 执行中国市场 T+1 卖出约束。

### 6.2 信号与执行时点

交易日 T 收盘后，只使用截至 T 日可见的数据计算信号；订单最早在下一可交易日 T+1 开盘执行。

不得使用以下方式：

- 使用 T 日收盘数据生成信号后又按 T 日收盘价成交。
- 使用完整回测区间最高价、最低价反推历史斐波那契位置。
- 在波段拐点尚未被后续 K 线确认时提前使用该拐点。
- 在趋势线触点尚未发生时提前认定趋势线有效。

信号冲突规则：

- 持仓期间再次出现买入信号：忽略，并记录 `ignored_reason=already_holding`。
- 同一日同时满足买入与卖出条件：卖出优先，买入信号作废。
- 同一日同时触发风险退出和普通策略卖出时，只生成一个 `risk_exit` 卖单，风险退出优先，并在审计记录中保留全部触发原因。
- T+1 开盘买入的仓位，即使买入当日盘中触发止损或止盈，卖单最早也只能在下一个交易日开盘执行。

### 6.3 订单类型与生命周期

订单分为：

- `strategy`：普通策略信号订单。
- `risk_exit`：止损、止盈等风险退出卖单。

不可成交时：

- 停牌：订单顺延。
- 一字涨停且为买单：顺延。
- 一字跌停且为卖单：顺延。
- 资金不足：按资金重新计算整数手；不足一手则拒绝并记录原因。

顺延规则：

- 顺延上限默认 5 个交易日，可配置。
- 每个不可成交交易日将 `deferred_trading_days` 加 1；达到上限后取消并记录 `expired`。
- `strategy` 订单顺延期间，基于最近一个已经完成的交易日收盘信号判断是否反转；反转时取消并记录 `signal_reversed`。
- `risk_exit` 订单不得因新的买入信号或其他普通策略信号而取消，只能成交、因不可交易继续顺延，或达到顺延上限后超期。

回测结束仍有持仓时，默认按最后一个交易日收盘价计算期末市值，不强制虚构卖出；结果中单独显示未平仓状态和未实现盈亏。

回测结束时仍未成交的挂单统一记录为取消，原因 `period_end`，并在挂单状态和信号审计中可见。

### 6.4 涨跌停保守判据

一字板判定：

```text
当日最高价 == 当日最低价
且 |涨跌幅| >= 板块基础阈值 × 97%
```

板块基础阈值：

- 主板：10%。
- 创业板、科创板：20%。
- 北交所：30%。

历史 ST 状态首期不做精确识别，统一使用板块基础阈值和上述保守判据，并在结果中标注这一假设。涨跌幅字段缺失时可根据前收盘价计算；无法可靠计算时不得武断判定一字板，必须记录数据限制。

## 7. 指标定义

全部指标模块接受任意 bar 序列输入，不依赖日线特有的数据结构，为二期周线重采样预留；首期仅传入日线 bar。

### 7.1 均线

默认参数：

- 短期均线：MA5。
- 长期均线：MA20。
- 计算字段：收盘价。

基础信号：

- 金叉：前一日 `MA5 <= MA20`，当日 `MA5 > MA20`。
- 死叉：前一日 `MA5 >= MA20`，当日 `MA5 < MA20`。
- 多头状态：`MA5 > MA20`。
- 空头状态：`MA5 < MA20`。

周期可以在 UI 中修改，但必须满足短周期小于长周期。

### 7.2 确认波段拐点

斐波那契和趋势线共用无前视的确认拐点：

- 默认左侧 K 线数：3。
- 默认右侧 K 线数：3。
- 某日高点高于其左右各 3 根 K 线高点时，为候选波段高点。
- 某日低点低于其左右各 3 根 K 线低点时，为候选波段低点。
- 右侧 3 根 K 线全部结束后，候选点才成为“已确认拐点”。
- 每个拐点必须保存拐点日期和 `confirmed_at` 日期。
- 在 `confirmed_at` 以前，策略不得访问或使用该拐点。

左右确认数量可调。所有回测记录应保存信号计算时实际可见的拐点。

### 7.3 斐波那契回撤

默认回看窗口为最近 60 个交易日，只使用窗口内已确认的波段。

上升波段要求：

- 先出现有效波段低点 L，后出现有效波段高点 H。
- H > L。
- 高低点间至少间隔 5 个交易日。
- `(H - L) / L >= 最小振幅`，默认最小振幅为 5%，可调。

个股建议最小振幅为 5%～10%，宽基 ETF 可以手动下调。未达到最小振幅的波段不参与斐波那契计算。

上升波段回撤价位：

```text
回撤位(r) = H - (H - L) × r
r ∈ {0.236, 0.382, 0.5, 0.618, 0.786}
```

默认使用离散关键位模式：

- 关键位集合：38.2%、50%、61.8%。
- 每个关键位容差：±1%，可调。
- K 线与某关键位容差带相交即视为盘中触及：

```text
low <= 关键位 × (1 + 容差)
且 high >= 关键位 × (1 - 容差)
```

- 同一天触及多个关键位时记录全部触及结果；任一关键位触及即可满足“位置触及”子条件。

原 38.2% 至 61.8% 宽区间模式保留为可配置选项，默认关闭。

默认反弹确认：

- 当日 K 线触及离散关键位容差带，或在区间模式下进入关注区；并且
- 当日收盘价高于前一日收盘价；并且
- 当日收盘价高于当日开盘价。

多波段选择：60 日窗口内存在多个合格 L→H 波段时，取确认时间最近的一组，不进行参数放宽或主观优选。

默认失效条件：收盘价跌破 61.8% 回撤位 1% 以上，或跌破本次波段低点。

策略 B/D 入场时，必须把当时使用的 L、H、振幅、确认时间和各回撤位保存为波段快照。持仓期间新形成的波段不得改变本次持仓的波段失效判断。

窗口内无合格波段时，斐波那契条件恒不成立、不交易；禁止放宽振幅、扩大容差或使用未确认拐点作为 fallback。

### 7.4 趋势线

第一版使用最近两个已确认波段低点构造上升支撑候选线：

- 第二个低点必须高于第一个低点。
- 两个低点至少间隔 5 个交易日。
- 仅使用最近两个已确认低点；条件不满足时判定当前无候选线，不回溯搜索其他低点组合。
- 趋势线按交易日序号线性延伸，不按自然日延伸。

两点连线仅为候选线，策略不可使用。候选线需要触点验证：

- 两个锚点计为 2 个触点。
- 只统计第二个锚点 `confirmed_at` 之后发生的验证触点。
- 后续某根 K 线的最低价进入趋势线 ±0.5% 容差范围，且当日收盘价未低于趋势线 1% 以上，记为一次验证触点。
- 总触点数（含 2 个锚点）达到 3 个时，候选线升级为有效趋势线。
- `touch_count`、锚点和生效日期必须写入审计数据。

默认有效跌破：收盘价低于趋势线 1% 以上。

下降压力线使用最近两个逐步降低的已确认波段高点对称构造，验证触点使用最高价判断。首期组合策略以上升支撑线有效为主。

策略只能使用有效趋势线。触点不足时禁止降级使用两点候选线；窗口内没有有效趋势线是合法常态，可能导致策略 C/D 数月不交易，不属于故障。

拐点间隔、触点容差、最小触点数和突破阈值均可调。

## 8. 策略定义

一次回测 run 对用户勾选的策略集合分别独立模拟。各策略共享同一份 K 线、指标预计算结果、初始账户参数和费率快照，但持有各自独立的现金、订单、持仓和净值。

### 8.1 策略 A：纯均线

买入：MA5 上穿 MA20。  
卖出：MA5 下穿 MA20，或触发止损/止盈。

### 8.2 策略 B：均线 + 斐波那契

买入需同时满足：

- MA5 > MA20；
- 价格触及斐波离散关键位容差范围；若用户启用区间模式，则进入指定关注区；
- 出现反弹确认。

卖出满足任一：

- MA5 < MA20；
- 入场时绑定的斐波那契波段失效；
- 触发止损或止盈。

### 8.3 策略 C：均线 + 趋势线

买入需同时满足：

- MA5 > MA20；
- 存在已经通过触点验证的有效上升支撑线；
- 收盘价未有效跌破该支撑线。

卖出满足任一：

- MA5 < MA20；
- 收盘价有效跌破上升趋势线；
- 触发止损或止盈。

### 8.4 策略 D：均线 + 斐波那契 + 趋势线

买入需同时满足：

- MA5 > MA20；
- 存在已经通过触点验证的有效上升支撑线；
- 价格触及斐波离散关键位容差范围；若用户启用区间模式，则进入指定关注区；
- 出现反弹确认。

卖出满足任一：

- MA5 < MA20；
- 有效跌破上升趋势线；
- 入场时绑定的斐波那契波段失效；
- 触发止损或止盈。

### 8.5 风险参数

默认值：

- 固定止损：相对实际买入成交价 -8%。
- 固定止盈：相对实际买入成交价 +15%。
- 盘中触及止损：当日最低价 <= 止损价。
- 盘中触及止盈：当日最高价 >= 止盈价。
- 同一根日 K 同时触及止盈和止损时，保守判定止损先触发。
- 触发后生成下一可交易日开盘卖单，并按卖出滑点成交。
- 买入成交当日触发时，受 T+1 约束，最早在再下一个交易日开盘卖出。

交易记录必须同时保存理论触发价、实际成交价和二者偏差。跳空时实际成交价可能显著偏离理论触发价。

止损、止盈可以单独关闭或调整。首期不默认启用移动止损。

## 9. 买入持有基准

- 从回测区间首个交易日开始尝试按同一初始资金买入最大整数手；若当天停牌或一字涨停无法成交，则顺延至下一可交易日，并在结果中标注基准实际建仓日。
- 使用与策略相同的佣金、税费、过户费和滑点。
- 持有到回测区间最后一个交易日收盘，按期末市值计算。
- 同时展示基准毛收益和净收益。
- 基准期末不卖出，其账户累计盈亏明确记为“简单持有浮盈亏”，不得误称为已实现收益；该数值已包含建仓成本，不包含未发生的卖出费用和税费。
- 策略超额收益以双方净收益之差计算。
- 基准净值按 run 保存一份，由所有策略共享。

## 10. 输出指标

### 10.1 收益与风险

- 初始资金、期末资产。
- 累计毛收益率、累计净收益率。
- 年化收益率。
- 买入持有净收益率。
- 简单持有浮盈亏金额及浮盈亏率，并与当前策略期末盈亏展示差额。
- 净超额收益率。
- 最大回撤及回撤区间。
- 夏普比率：默认年化无风险利率 2%、年化交易日 252，均可配置并保存到参数快照。
- 收益波动率。
- 资金使用率。

### 10.2 交易与信号统计

- 完整交易次数。
- 买入次数、卖出次数、未成交次数。
- 胜率。
- 盈亏比：盈利交易的已实现净盈利总额 ÷ 亏损交易的已实现净亏损绝对值；无亏损交易时返回空值，界面显示 `--`，不得误显示为 0。
- 平均单笔毛收益、净收益。
- 最佳与最差单笔交易。
- 平均持仓天数。
- 策略换手率：区间内买入成交额合计 ÷ 平均总资产。
- 当前未平仓持仓和未实现盈亏。
- 各策略信号触发次数。
- 各条件未满足天数及原因分布。
- 订单顺延、超期、信号反转、已持仓忽略等原因分布。

### 10.3 成本统计

- 累计佣金。
- 累计印花税。
- 累计过户费。
- 累计滑点成本。
- 总交易成本。
- 总成本占初始资金比例。
- 总成本占毛利润比例。
- 扣费前后收益差异。
- 平均每轮交易成本率。
- 单轮交易盈亏平衡所需涨幅。

## 11. 图表与交互

回测入口放在当前 `/analysis?symbol=...` 页面，与当前证券代码联动。右侧主工作区增加“K 线回测”标签页，避免挤压现有协同工作流；当前左侧聊天区和现有智能分析流程不被破坏。

### 11.1 参数区

- 当前证券和品种识别结果。
- 开始、结束日期，默认动态上一完整自然年。
- 初始资金和最大仓位。
- MA 周期。
- 波段确认参数和斐波那契窗口。
- 斐波模式：离散关键位或宽区间。
- 离散关键位容差、最小波段振幅。
- 趋势线容差、最小触点数。
- 止盈、止损。
- 挂单顺延上限。
- 佣金、最低佣金、印花税、过户费、滑点。
- 复权方式。
- 待比较的策略组。
- 使用缓存或强制刷新。
- “恢复默认参数”和“开始回测”。

run 处于 `pending` 或 `running` 时，当前页面必须禁用重复提交并持续展示状态；组件卸载或切换 run 时应停止旧轮询。

选择指数时禁用提交按钮，并显示“首期暂不支持指数回测”。

### 11.2 结果区

- 核心指标卡片。
- 策略净值与买入持有净值对比曲线。
- 回撤曲线。
- K 线、MA5、MA20。
- 有效趋势线及触点数。
- 合格波段的斐波那契水平线和关注区域。
- 买入、卖出、止盈、止损标记。
- 成本构成图。
- 多策略对比表，包含各策略期末盈亏与简单持有浮盈亏。
- 信号触发次数和条件未满足原因分布。
- 逐笔交易明细、挂单状态和未成交原因。

价格图必须提供独立图层管理，可分别切换短期 MA、长期 MA、有效趋势线、斐波水平线和买卖标记，并提供“精简”和“全部显示”预设。默认精简视图保留双均线与买卖标记，隐藏趋势线和斐波水平线；用户选择应在本机持久化，切换图层不得重建图表或丢失当前缩放位置。

启用趋势线或斐波图层时，只渲染有效趋势线和合格波段的斐波水平线。若为了审计展示候选线，必须使用明显弱化的虚线并标明“候选，不参与信号”。

斐波图层默认只展示最新一组合格波段，水平线的起止日必须与该波段在逐日指标快照中的实际可见区间一致，不得延伸到波段失效后的 K 线。

策略 C/D 零交易时必须展示条件未满足分布，不能显示为空白或报错。

图表缩放或拖动时，K 线、指标线和交易标记必须同步；价格图提供“重置视图”，一键恢复完整时间范围、默认位置和价格轴自动缩放。移动端允许横向滚动，不得裁掉关键参数和结果。

### 11.3 现有图表栈适配

- K 线、均线、趋势线、斐波水平线和买卖标记使用项目已有 `lightweight-charts 5.x`。
- 净值、回撤和成本构成使用项目已有 Recharts。
- 不新增 klinecharts 或 ECharts，避免重复依赖和交互冲突。
- 回测图表使用独立组件，不把复杂结果逻辑直接堆入现有 `KlinePanel`。

## 12. 持久化、任务与 API

### 12.1 API

新模块使用独立命名空间：

```text
POST   /v1/kline-backtests
GET    /v1/kline-backtests/{run_id}
GET    /v1/kline-backtests?symbol=...
DELETE /v1/kline-backtests/{run_id}
GET    /v1/kline-backtests/{run_id}/trades?strategy=A
GET    /v1/kline-backtests/{run_id}/equity?strategy=A
GET    /v1/kline-backtests/{run_id}/signals?strategy=A
```

run 详情在完成后返回各策略摘要和基准摘要；逐日净值、逐笔交易和信号审计通过分页或按策略子接口读取，避免详情响应无限膨胀。

首期不提供运行中任务取消。对 `pending` 或 `running` run 调用 DELETE 返回 409；仅允许删除 `completed` 或 `failed` run。

`POST` 立即返回 HTTP 202：

```json
{"run_id": "...", "status": "pending"}
```

前端轮询 run 状态。状态机：

```text
pending -> running -> completed | failed
```

### 12.2 专用执行队列

- 回测使用独立线程池，默认最大并发为 1，可通过环境变量调整。
- 不与大模型分析线程池共用执行槽。
- 不引入 Celery、Redis 或新任务基础设施。
- API 创建并提交任务后立即返回，不阻塞请求。
- 计算主要在内存完成，状态更新和结果落库使用短事务；不得在整个回测期间持有长事务。
- 只有全部结果成功落库后才能将 run 标记为 `completed`；持久化失败必须回滚并标记为 `failed`。

### 12.3 孤儿恢复

回测队列存在于 app 进程内存中。app 容器启动时，将数据库内遗留的 `pending` 和 `running` run 一律标记为：

```text
status = failed
error_code = orphaned
```

首期不自动重新入队。

孤儿恢复只能由 app 容器的 FastAPI lifespan 执行，不能放入 app 与 scheduler 共用的 `init_db()`，也不能由 scheduler 容器执行，以免 scheduler 重启时误杀 app 中真实运行的回测。

### 12.4 数据模型

建议结构：

```text
kline_cache
  symbol, adjust, start, end, fetched_at, expires_at,
  akshare_version, source_api, data_hash, payload

kb_runs
  run_id, user_id, symbol, instrument_type, start, end, status,
  params_snapshot, fee_snapshot, data_hash, actual_data_range,
  cache_version, error_code, error, created_at, started_at, finished_at

kb_strategy_results
  run_id, strategy_key, metrics, signal_stats, open_position

kb_trades
  run_id, strategy_key, signal_date, planned_date, actual_date,
  order_type, side, theory_trigger_price, exec_price, qty,
  commission, stamp_tax, transfer_fee, slippage_cost,
  trigger_reason, order_outcome, wave_snapshot,
  cash_after, position_value_after

kb_equity
  run_id, strategy_key, date, cash, position_value, total, drawdown

kb_benchmark_equity
  run_id, date, total, drawdown

kb_signals_audit
  run_id, strategy_key, date, ma_values, visible_pivots,
  fib_levels, swing_amplitude, trendline_price, touch_count,
  decision
```

`kb_trades` 记录全部订单生命周期，而不只是已成交记录；顺延后成交、资金不足、超期、信号反转和期末取消等结果均通过 `order_outcome`、原因和顺延天数保留，为订单统计与审计提供数据来源。

所有金额字段按可精确保存十进制金额的方式设计，不能以 Python float 作为账户持久化来源。

### 12.5 用户隔离

- `user_id` 只存于父表 `kb_runs`。
- 子表不冗余 `user_id`。
- run 列表、详情、删除、交易和净值接口全部通过 `kb_runs.user_id` 或 join `kb_runs` 校验当前用户所有权。
- 未拥有的 run 统一返回 404，避免泄露其存在性。
- 所有新接口接入现有网页/API Token 身份认证。

### 12.6 SQLite 约束

- 当前部署由 app 与 scheduler 两个容器共享 SQLite WAL 数据库，回测写入必须使用短事务和分批落库。
- 当前 SQLite 外键约束未启用；删除 run 时必须在单个事务中显式删除全部子表记录，不能只依赖级联删除声明。
- 新表通过现有 SQLAlchemy `Base.metadata.create_all()` 创建；若模型拆到独立模块，必须保证 `init_db()` 调用前完成模型导入。
- 后续已有表发生结构变化时，按项目现有轻量迁移方式显式处理，不能假定 Alembic 已存在。

## 13. 异常与提示

- 证券不存在或不支持时给出明确提示。
- 指数返回“首期暂不支持指数回测”，不得误识别为股票。
- 数据缺失、预热不足、AkShare 失败时不得生成伪结果。
- AkShare 连接失败必须在有限次数重试后终止，并向调用方返回明确的数据源连接错误。
- 数据源连接失败时显示本次锁定的供应商，并允许用户明确选择其他已支持供应商重新创建 run；禁止在原 run 内静默换源。
- 实际数据区间与用户选择区间不一致时必须显示差异。
- 尚未收盘的当日 K 线被排除时应在数据口径中说明。
- 指标长期无法形成有效波段或趋势线时显示“条件不足”，不是系统错误。
- 回测期间无交易时正常返回，并展示各条件未满足天数统计。
- 禁止通过放宽趋势线触点、波段振幅、斐波容差或拐点确认条件来强行产生交易。
- 参数非法时在提交前校验，例如短均线不得大于等于长均线。
- 同一证券、相同标准化数据哈希和相同参数快照应产生一致结果。
- AkShare 字段变化时明确报错并记录接口，不得错列或猜测字段。

## 14. 测试要求

### 14.1 单元测试

- 股票和场内基金识别；指数拒绝；北交所代码标准化。
- 万 1.15、万 1 与免 5 计算。
- 股票卖出印花税和基金免印花税。
- 股票双向万 0.1 过户费。
- 双向滑点归因不重复扣款。
- 账户全 Decimal、分级舍入、100 股整数手和资金边界。
- MA 金叉、死叉。
- 延迟确认的波段拐点和 `confirmed_at` 可见性。
- 斐波离散位 K 线区间相交、±1% 容差和最小振幅过滤。
- 多波段最近确认选择和入场波段快照绑定。
- 趋势线触点计数；第二锚点确认后才开始验证；触点不足 3 时不可用。
- 禁止无有效趋势线或波段时降级 fallback。
- 止盈、止损盘中触及和同 K 线保守止损。
- T 日信号只能在 T+1 或以后成交。
- 买入当日触发风险条件时最早 T+2 卖出。
- 持仓中忽略买入信号；同日买卖冲突卖出优先。
- 风险退出和普通卖出同日触发时只生成一个风险退出单，并保留全部原因。
- 策略订单反转取消；风险退出订单不因反转取消。
- 挂单顺延 5 日达到上限后取消。
- 停牌和涨跌停顺延。
- 最大回撤、夏普、胜率、盈亏比、策略换手率和成本统计。
- 标准化 K 线哈希在固定输入下稳定。
- 未收盘当日 K 线排除。

### 16.2 引擎处理顺序

每个策略账户按统计区间交易日顺序执行：

```text
for T in 统计区间交易日:
  1. 使用 T 日开盘数据处理此前挂单
     - 检查停牌、一字板、资金和顺延上限
     - strategy 单检查基于最近一个已完成交易日收盘信息的信号反转
     - risk_exit 单禁止因普通信号反转取消
     - 可成交则按开盘价 ± 滑点成交并更新账户

  2. 对持仓检查 T 日盘中风控（包含 T 日开盘新买入的持仓）
     - low <= 止损价：生成风险退出单
     - high >= 止盈价：生成风险退出单
     - 同时触及：止损优先
     - 订单计划于下一可交易日开盘执行

  3. T 日收盘后计算策略信号
     - 只读取 confirmed_at <= T 的拐点
     - 趋势线只读取已经达到最小触点数的有效线
     - 斐波只读取合格波段及默认离散关键位
     - 已持仓买入信号忽略；同日买卖冲突时卖出优先
     - 普通信号生成 strategy 订单

  4. 计算并暂存 T 日净值和信号审计

期末:
  - 未平仓持仓按最后收盘价计值
  - 计算策略指标、基准和成本归因
  - 使用短事务批量落库
  - run 更新为 completed；任何不可恢复异常更新为 failed
```

指标可以对完整标准化序列预计算，但每个拐点、波段和趋势线必须携带可见日期；引擎在 T 日只能读取可见日期不晚于 T 的结果，使预计算与逐日计算在信息集合上等价。

## 17. 已确认决策

- 回测以纯 K 线确定性计算为主，不调用 GLM-5.2。
- 数据源严格使用独立 AkShare 入口；每个 run 显式锁定一个供应商，不静默跨供应商回退，换源必须创建新 run。
- 排除尚未收盘的当日 K 线，保存标准化数据 SHA-256。
- 首期回测单只 A 股股票或场内基金，明确拒绝指数。
- 默认区间动态取上一完整自然年。
- 一次 run 对多个策略使用独立虚拟账户。
- 使用均线、斐波那契回撤和趋势线。
- 斐波默认使用 38.2%、50%、61.8% 离散位 ±1%，按 K 线高低区间相交判断触及。
- 斐波波段默认最小振幅 5%，入场绑定波段快照，无合格波段时不 fallback。
- 趋势线至少 3 个触点才有效，只统计第二锚点 `confirmed_at` 之后的验证触点。
- 没有有效趋势线是合法常态，严禁降级使用两点候选线。
- 止损止盈使用盘中触及判定，次日开盘执行，同 K 线同时触及时止损优先。
- 普通信号收盘后产生，下一交易日开盘成交，并遵守 T+1。
- 挂单顺延上限默认 5 个交易日。
- 信号反转取消只适用于策略订单；风险退出单不得因普通信号反转取消。
- 完整计入交易费、税费和滑点。
- A 股佣金万 1.15 免 5，场内基金佣金万 1 免 5，所有费率可调。
- A 股过户费默认双向万 0.1，场内基金默认 0。
- 任务状态为 `pending -> running -> completed | failed`，使用专用并发 1 队列。
- 首期不支持取消活动 run；活动 run 不允许删除，且只有结果成功落库后才能标记完成。
- app 启动时将遗留 `pending/running` 标记为 `failed(orphaned)`；scheduler 不执行孤儿恢复。
- `user_id` 只保存在 `kb_runs`，子表通过 join 父 run 校验所有者。
- SQLite 外键未启用时显式删除子记录，不依赖级联。
- 北交所证券由新模块独立标准化。
- 前端沿用 lightweight-charts + Recharts，不新增图表库。
- 默认比较四组指标策略和买入持有基准。
